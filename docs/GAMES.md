# Game module integration

Import `registerApps` from `games/index.js`, call `registerApps(os)`, and link `games/styles.css`. Include `victory.js` alongside the two engine files; `index.js` imports it directly. The module uses the DOM helper and OS APIs in `../core/dom.js` and the supplied contract. Registered IDs: `minesweeper` and `solitaire`. All styles are scoped to `.mine-*` or `.sol-*` classes.

## Implemented behavior

**Minesweeper:** safe first click; a clear first-click neighborhood whenever the mine density permits it; flood reveal; right-click, Shift-click, F-key and menu flag mode; number-click chording; correct loss and victory detection; exposed mines and incorrectly flagged squares on loss; face-button reset; original-style segmented counters; elapsed seconds; Beginner (8 × 8, 10), Intermediate (16 × 16, 40), Expert (30 × 16, 99); validated Custom dialog; keyboard grid navigation; sound toggle; persistent fastest times and preferences; help and About menus. Large boards scroll within the application window.

**Solitaire:** shuffled 52-card Klondike deal; legal alternating descending tableau sequences; Kings in empty columns; suit-matched Ace-to-King foundations; automatic flip after clearing the visible part of a column; foundation-to-tableau moves; draw-one and draw-three; Standard, Vegas, and None scoring; standard move scoring, clock deductions and victory bonus; unlimited standard/no-score waste redeals; Vegas wagers, payouts and enforced stock-pass limits; optional cumulative Vegas balance and reset; full multi-move undo; elapsed time and move count; explicit deal confirmation during an active game; drag/drop, click-card/click-target, double-click to foundation, Tab/Enter and arrow-key controls; move hint; batch move to foundations; three selectable geometric card backs; status-bar and outline-dragging options; options, rules, scoring and About dialogs; a bouncing-card victory animation with persistent trails that stops on click or Escape. The clock pauses while minimized. The complete deal, elapsed time, and up to 100 undo steps are saved and restored automatically. Rules and scoring live in a DOM-free engine.

The foundation helper moves only cards that are legal at that moment. Undo can reverse each individual move. It does not decide whether sending a card to a foundation is strategically safe.

## Pure engine API

`minesweeper.js` exports `Minesweeper`, `MINE_LEVELS`, and `seededRandom(seed)`. Construct with `{ rows, cols, mines, rng, now }`. Use `reveal(index)`, `toggleFlag(index)`, `chord(index)`, `reset()`, `neighbors(index)`. Inspect `cells` (`mine`, `open`, `flag`, `adjacent`), `status`, `remaining`, `elapsed`, `exploded`, and `opened`. Status is `ready`, `playing`, `won`, or `lost`.

`solitaire.js` exports `Solitaire`, `SUITS`, `isRed(card)`, and `cardName(card)`. Construct with `{ rng, now, draw: 1 | 3, timed: boolean, scoring: 'standard' | 'vegas' | 'none', cumulative: boolean, bankroll: number }`. Vegas starts each game at the prior cumulative balance (or zero) minus 52, adds 5 per foundation card, removes 5 when a card leaves a foundation, and imposes one stock pass for draw-one or three for draw-three. Vegas has no clock deduction or win bonus. `newGame()` carries the balance when cumulative mode is enabled; pass `{ bankroll }` to override that opening balance. Use `newGame()`, `draw()`, `undo()`, `canMove(source, target)`, `move(source, target)`, `autoFoundation(source)`, `legalMoves()`, and `cardsAt(source)`. A source is `{ type: 'waste' }`, `{ type: 'foundation', index }`, or `{ type: 'tableau', index, cardIndex }`. A target is a foundation or tableau reference. Every pile's top is its last array element. `cardIndex` marks the start of a tableau sequence. Card fields are `id`, `suit` (`C`, `D`, `H`, `S`), `rank` (1–13), and `faceUp`. Inspect `tableau`, `stock`, `waste`, `foundations`, `history`, `moves`, `status`, `elapsed`, `displayScore`, `canDraw`, `canRedeal`, and `maxPasses`. `pause()` / `resume()` control the clock, and `setTimed(boolean)` changes timed scoring without losing settled penalties. `toJSON()` produces a versioned, JSON-safe game snapshot; `Solitaire.fromJSON(snapshot, { rng, now })` validates cards, uniqueness, pile rules, and scoring settings before restoring a game. It rejects inconsistent current positions and sanitizes the accepted state. Snapshots retain the last 100 undo records and exclude time while the window was closed. `displayScore` includes the running clock penalty; `score` is the settled internal score. Undo never rewinds real elapsed time.

For deterministic tests, use `rng: seededRandom(123)` and `now: () => milliseconds`.

## Verification and limits

Verified 100 seeded Minesweeper games for exact mine counts, safe first clicks, full-clear wins and zero remaining flags after victory. Verified 100 Klondike deals for expected column/stock sizes and unique cards, undo of draws, and 50,000 transitions preserving all 52 cards. Additional tests cover Vegas stock limits, cumulative wagers, no-score stock cycling, pause/resume, saved-game round trips, invalid/duplicate-card rejection, and 3,000 transitions across all scoring modes. JavaScript syntax checks passed. The owner should verify DOM integration, OS menu keyboard dispatch, animation and visual layout in the complete desktop.

This is a browser implementation of the games, with original SVG card/mine graphics and CSS card backs. It does not run the original Windows executables. Minesweeper best times and game preferences persist through `os.storage`; its current minefield lasts for the lifetime of the window. Solitaire game positions, cumulative Vegas balance, and preferences persist through `os.storage`. The current position is saved after every move, every 15 seconds, and on window close. Minesweeper positions are not resumed after closing. The Solitaire art and victory animation recreate the behavior using original vector/canvas graphics rather than shipping Microsoft game assets.
